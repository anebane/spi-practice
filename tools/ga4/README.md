```sh

python3 tools/ga4/fetch.py --days 28
```

## ⚠️ 残っている作業：サービスアカウントに閲覧権限を付ける

`analytics-reader@anebane-web-ops.iam.gserviceaccount.com` を
GA4の「プロパティのアクセス管理」に **閲覧者** で追加する必要がある。

**2026-08-27にブラウザから4通り試したが、いずれもGA4が
「このメールアドレスは Google アカウントと一致しません」で弾いた。**

試したこと（すべて同じエラー）:
1. プロパティレベルで追加（`fill` で入力）
2. プロパティレベルで追加（1文字ずつ入力）
3. **アカウントレベル**で追加（プロパティとは別の経路）
4. 「他のオプション」に警告を無視する選択肢がないか確認 → 無い

**原因はサービスアカウント側ではない。** 根拠:
- GCPコンソールで **状態「有効」** を確認。メールも完全一致
  （`analytics-reader@anebane-web-ops.iam.gserviceaccount.com` / 鍵 `d9489bbc...`）
- **同じサービスアカウントを GSC は受け付けており、実際に稼働している**
  （`tools/gsc/fetch.py` は毎週動いている）

∴ **GA4側のユーザー追加UIがサービスアカウントを弾いている**と判断した。

### 次に試す順序

1. **時間をおいて再試行**（一時的な不具合の可能性。まずこれ）
2. **Admin API の `create_access_binding` で追加する。**
   ただしこのAPIを叩くには GA4 の編集権限を持つ資格情報が要り、
   サービスアカウント自身にはまだ権限が無い（鶏と卵）。
   矢野さんのGoogleアカウントでOAuthクライアントを作って通す必要がある
2. 別のブラウザ／シークレットウィンドウで手動追加

これが通るまで `fetch.py` は 403 を返す（**通信自体は到達している**ので、
残りはこの権限だけ）。

## 実装上の注意

- **`transport="rest"` は必須。** 既定の gRPC はこの環境で IPv6 に振られて
  `503 No route to host` になる（2026-08-27に実測）。
- **カスタムディメンションは遡及しない。** 登録前に送ったデータは
  そのディメンションで集計できない。だから先に登録した。
- `template_id` は 2026-08-27 から送っている。それ以前は `question_id`
  （毎問ユニーク）だったので集計できない。
